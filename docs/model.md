# model: контракт с моделью

Пакет `model` описывает разговор с LLM и ничего не знает о провайдерах. Реализации лежат в подпакетах.

## Типы

| Тип | Что это |
|---|---|
| `Message` | реплика: `Role` (`system`, `user`, `assistant`, `tool`), `Content`; у ассистента — `ToolCalls`, у результата инструмента — `ToolCallID` |
| `ToolCall` | просьба модели вызвать инструмент: `ID`, `Name`, `Arguments` (JSON) |
| `ToolDef` | инструмент, каким его видит модель: имя, описание, JSON Schema аргументов. Обычно его строит `tool.Set.Defs` |
| `Request` | `Messages`, `Tools`, `Format` (ответ строго в JSON по схеме), `ReasoningEffort` на один вызов |
| `Response` | `Message` ассистента и `Usage` (токены промпта и ответа) |

## Model

```go
type Model interface {
    Chat(ctx context.Context, req Request) (Response, error)
    Stream(ctx context.Context, req Request, onDelta func(text string)) (Response, error)
}
```

`Stream` отдаёт текст кусками по мере генерации. Вызовы инструментов приходят уже собранными в `Response`.
Агент всегда пользуется `Stream`. `Chat` нужен для вызовов вне цикла: классификация, JSON по схеме.

**Ошибки.** Адаптер оборачивает сбои в:
- `ErrUnavailable` — сеть, таймаут, 429, 5xx. Можно повторить, в том числе на другой модели.
- `ErrBadResponse` — ответ нельзя использовать, например аргументы инструмента не JSON.

Остальные отказы провайдера (400, 401) возвращаются как есть.

**`Format` и инструменты вместе не шлите.** Локальная Qwen при заданном формате не вызывает инструменты.
Сначала ход с инструментами, потом отдельный вызов `Chat` с `Format`.

## Provider: пул моделей

```go
type Provider interface {
    Acquire(ctx context.Context, onWait func()) (m Model, release func(), err error)
}
```

Это интерфейс без реализации в loom. Нужен, когда моделей несколько (своя машина, облако), и у каждой свой лимит
одновременных запросов. Если `Model`, переданная в `agent.New`, реализует ещё и `Provider`, агент:

1. в начале хода вызывает `Acquire` и ждёт свободную модель. Пока ждёт, через `onWait` срабатывает `Stream.Waiting`;
2. держит полученную модель весь ход, чтобы модель не менялась посреди цикла инструментов;
3. отсчитывает таймаут хода с момента получения модели: время в очереди ход не съедает;
4. вызывает `release` в конце хода.

Чтобы пул работал и для одиночных вызовов, пусть он реализует и `Model`: на каждый вызов берёт место и сразу
его отдаёт. Переход на другой эндпоинт при `ErrUnavailable` до первого токена — забота реализации пула.

## openai

`model/openai` — `Model` для любого OpenAI-совместимого `/chat/completions`.

```go
m := openai.New(openai.Config{
    BaseURL:         "http://localhost:11434/v1", // заканчивается на /v1
    Model:           "qwen3.6:35b-a3b",
    APIKey:          "ollama",
    ReasoningEffort: "none", // для Qwen: без рассуждений, вызовы инструментов быстрее
    MaxRetries:      0,      // повторы SDK на 429 и 5xx; 0 — одна попытка
    Temperature:     nil,    // nil — значение модели по умолчанию
})
```

| Поле | Поведение |
|---|---|
| `ReasoningEffort` | уходит как `reasoning_effort`, пустое не отправляется. `Request.ReasoningEffort` перекрывает его на один вызов. Для API, которые не знают этот параметр, оставь пустым |
| `Temperature` | отправляется, только если задана |
| `Format` | уходит как `response_format: json_schema` со `strict: true` |

Стриминг собирает вызовы инструментов из дельт и просит у провайдера счёт токенов (`include_usage`). Текст,
который модель пишет перед вызовом инструмента, приходит в `onDelta`, а агент потом шлёт `Stream.Reset`.

## Своя модель

Реализуй два метода `Model`. Для проверки контракта собери ход с `agent.New(yourModel)` и сравни с тестами
`model/openai`: туда входят роли сообщений, вызовы инструментов, классификация ошибок и стриминг.
